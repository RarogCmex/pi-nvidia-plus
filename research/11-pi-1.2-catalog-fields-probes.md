# 11. Поля каталога pi 1.0.2–1.2.0 для NIM: план проб

**Дата:** 2026-10-13. **Тип: план, не свидетельство.** Ни один ответ в этом
файле живой пробой ещё НЕ получен; всё «гипотеза» помечено. Офлайн-факты
(схема pi, исходники) указаны отдельно и являются свидетельствами.

**Вопрос:** pi 1.0.2 принёс `samplingParamsByThinkingLevel`, pi 1.2.0
опубликовал схемы конфигов и заодно видимыми стали поля `maxTokens`,
`inputLimits` на модель и новые `compat`-флаги (`thinkingTokenBudgetField`,
`supportsThinkingTokenBudget`). Какие из них применимы к каталогу NIM и
что для записи в `overrides/models.json` нужно померить живьём?

## §0. Что уже проверено офлайн (свидетельства)

- `samplingParamsByThinkingLevel` существует и применяется для
  OpenAI-совместимых API (changelog pi 1.0.2, #9776; в схеме pi 1.2.0 —
  `https://pi.dev/schemas/models.schema.json`, `$defs.SamplingParamsByThinkingLevel`;
  в бандле: `$PI/dist/core/model-config.js`, `ModelOverrideSchema` строки 39–53).
- Схема покрывает все поля, что сейчас пишем: `reasoning`,
  `thinkingLevelMap`, `contextWindow`, `maxTokens`, `inputLimits`,
  `samplingParams(ByThinkingLevel)`, `compat.*` — всё родное, а значит
  проба сводится к поиску ЗНАЧЕНИЙ, не к обходу валидации.
- С pi 1.2.0 наш `models.json` пишется с маркером `$schema`
  (`extensions/merge-models.ts` → `withModelsSchema`; пункт 2 из плана
  обновления — сделан).

## §1. `samplingParamsByThinkingLevel` — какие модели пробовать

**Гипотеза H1.** У reasoning-моделей NIM рекомендованный сэмплинг для
режима «думает» отличается от режима «не думает» (у deepseek-семейства
карточки исторически советовали `temperature` 0.6/1.0; у gpt-oss — иное).
Если это подтверждается, pi подставит параметры сам — вместо инъекций в
`transform.ts` (которые сейчас про сэмплинг молчат).

Кандидаты (все — модели, по которым у нас есть `thinkingLevelMap`, т.е.
мы уже знаем, как переключается мышление):

1. `nvidia/nemotron-3-super-120b-a12b`, `nvidia/nemotron-3-ultra-550b-a55b`,
   `nvidia/nemotron-3-nano-omni-30b-a3b-reasoning`, `nvidia/nemotron-3.5-lightning-30b-a3b`
   — семейство с картой off/max.
2. `openai/gpt-oss-20b` — особый режим `compat.supportsReasoningEffort`
   (карта `off→null`); сэмплинг gpt-oss-семейства в карточке NIM не заявлен —
   открытый вопрос.
3. `deepseek-ai/deepseek-v4-flash-0731`, `deepseek-ai/deepseek-v4.1-flash`.
4. `moonshotai/kimi-k3` (после 07 карта известна), `z-ai/glm-5.3`,
   `z-ai/glm-5.3-flash`, `poolside/laguna-xs-2.1`.

**Протокол (нужен ключ, согласие пользователя — см. §4):**
для каждой модели оба конца карты (`thinking on` и явный `off`), по 2
коротких генерации с восьмью точками сетки `{0.0, 0.6, 1.0, 1.6}` ×
сэмплинг по умолчанию; смотрим не «красоту», а признак деградации
(коллапс повторений по `classifyDegenerate` из 06 §3–4, пустота по
`stop`). Решение «разный рекомендованный сэмплинг» принимается, только
если разница повторяется в 2+ раундах (правило из
«Методологические оговорки» 02) и не объясняется маршрутом (10 §1:
зависимость «модель × выход» — пробы гонять на ОДНОМ выходе).

**Запись при подтверждении:**
`modelOverrides.<id>.samplingParamsByThinkingLevel = { medium: {temperature: …}, off: {temperature: …} }` — в overrides, evidence = этот файл.

## §2. `maxTokens` — где карточка знает потолок вывода

**Фон.** `transform.ts` дефолтит `max_tokens`, когда pi не задал; это
буфер, не знание. Настоящий потолок вывода pi использует при расчёте
входного остатка (после 1.1.0 — 3.5 симв/токен), т.е. заниженный дефолт в
карточке режет длинные ответы, а завышенный — сжимает промпт напрасно.

**Кандидаты (гипотеза H2: встроенный каталог занижает либо молчит):**
- `nvidia/nemotron-3-super-120b-a12b`, `nvidia/nemotron-3.5-lightning-30b-a3b`
  — контекст 1M уже подтверждён живой пробой (10 §2); потолок ВЫВОДА не
  проверен (гипотеза: 64K или кратно; карточка build.nvidia.com молчит).
- `deepseek-ai/deepseek-v4.1-flash` — встроенная карточка 384 000 вывода
  (10 §2), подтверждена сверкой карточки, но генерящей пробой до потолка
  не упиралась.
- `moonshotai/kimi-k3` — 131 072 в карточке оверрайдов; источник — чужая
  модельная карта, не проба.

**Протокол:** `max_tokens` сознательно выше подозреваемого потолка
(`131073`, `262145`) — ищем либо 400 с текстом лимита, либо отказ
потолком по факту (`finish_reason: "length"` на дешёвом стриминге не
подходит: сжечь сотни тысяч токенов генерации ради оракула нельзя;
порядок: сначала ключless/дешёвые ветки — 400-оракул, карточка
build.nvidia.com; генерацию-тестовую подводку в виде
`max_tokens = потолок` + короткий ответ — только если опечатка копеечная).

## §3. `inputLimits` — vision-модели

**Гипотеза H3.** У vision-моделей NIM есть жёсткий потолок размера
изображения/запроса, и pi может ресайзить ДО запроса (поля `inputLimits.images.resize`
в схеме 1.2.0), вместо 413/cut от шлюза.

**Кандидаты:** модели с `input: ["text","image"]` в живом каталоге —
`deepseek-ai/deepseek-v4.1-flash` (10 §2), nemotron-nano-vl-8b,
llama-3.2-11b/90b-vision-instruct, gemma-3-27b-it — список достаётся
keyless: `GET /v1/models` + фильтр по input-модальностям (исследование
02 о том, что каталог keyless).

**Протокол:** лестница размеров (1K×1K, 4K×4K, 8K×8K; base64-потолок
запроса 4/8/16 МБ) до первого 4xx с текстом лимита. Никакой генерации с
картинками на большом контексте — только отказ-оракулы (дешёво, как 09 —
auth раньше резолва функции, а валидация тела раньше генерации).

## §4. Ограничения прогона

- Живые пробы тратят квоту — только по явной просьбе пользователя
  (правило репозитория). Этот файл — очередь, а не запуск.
- Пробы мышления и лимитов — на одном выходе (прямом или закреплённом
  пином), иначе фактор «модель × выход» (10 §1) смешивается с фактором
  уровня мышления.
- Никакие значения не попадают в `overrides/models.json` без LIVE-пробы:
  карточки build.nvidia.com — полуфакт (10 §2 показал, где они расходятся
  с живым ответом), семейная экстраполяция — только гипотеза.
- Даты прямо в значениях: как и в `DEAD_MODELS`, каждая подтверждённая
  запись каталога получает дату в комментарии/свидетельстве — NIM снимает
  и меняет модели без предупреждения.

## §5. Что НЕ делаем из нового pi

Per-key OpenRouter каталоги, OSC52-clipboard, `reachesTools`/алиасы
неймспейсов, рендер-контексты (`durationMs`, `outputPad`), новые
классификаторы (llama.cpp, Clef), `agent_settled.aborted` и новая
семантика `before_agent_start` — всё это инструментарий/события, куда
расширение не лезет (провайдер-гейт `provider === "nvidia"`).
