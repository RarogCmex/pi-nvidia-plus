# pi-nvidia-plus — цель разработки

Расширение для pi, которое **улучшает встроенный провайдер `nvidia` на месте**,
не создавая дублирующего провайдера. Пользователь продолжает выбирать `nvidia/...`
и свой уже настроенный ключ — расширение только чинит то, что встроенный
провайдер не умеет.

## Предпосылки (что не так со встроенным `nvidia`)

Факты, проверенные по `pi-ai/dist/providers/data/nvidia.json` и живому каталогу NIM:

1. **Thinking не управляется.** У почти всех 32 моделей стоит
   `supportsReasoningEffort: false` и нет ни `thinkingLevelMap`, ни `thinkingFormat`.
   Исключение — только `deepseek-ai/deepseek-v4-flash-0731` (high/max).
   Выбранный уровень (`--thinking high`, Shift+Tab) молча отбрасывается:
   `off` и `high` дают одинаковый запрос, модель работает в дефолтном режиме
   хостинга (обычно «думает всегда»).
2. **Устаревший каталог.**
   - `deepseek-ai/deepseek-v4-flash` / `-pro` без суффикса сняты с NIM 2026-08-07
     (возвращают HTTP 410), встроенный список это не учитывает.
   - Часть моделей из встроенного списка фактически мертва на живом эндпоинте
     (по пробам: `google/gemma-3-*`, `mistralai/mistral-7b-instruct-v0.3`,
     `moonshotai/kimi-k2.6`, `nvidia/cosmos-reason2-8b`,
     `nvidia/llama-3.1-nemotron-70b-instruct`, `nvidia/llama-3.1-nemotron-ultra-253b-v1`).
   - Нет актуальных моделей: Gemma 4, Muse Glimmer, GLM-5.2, Step-3.7 Flash,
     Llama 3.2 1B/3B и др.
3. **Форма запроса.** Старые/мелкие модели NIM отвергают контент-массивы
   `[{type:"text",...}]` (нужна обычная строка) и запросы без `max_tokens`.
4. **Диагностика.** 429/5xx от NIM не показывают `retry-after` и request ID —
   рейт-лимиты трудно диагностировать.
5. **Эгресс-трафик.** Корпоративные среды иногда требуют выходить к NVIDIA с
   определённых точек: выделенный HTTP(S)-прокси, конкретный источник трафика,
   иногда другой выход для разных окружений. Встроенный провайдер использует
   глобальный транспорт — индивидуального прокси только для `nvidia` нет.

## Приоритеты

### P0 — рабочий thinking для моделей встроенного каталога
Инжектить управление мышлением через хук `before_provider_request`
(без кастомного `streamSimple` — как в `pi-extension-nvidia-nim`, чтобы не
трогать глобальный стриминг `openai-completions`):

- DeepSeek V4 (`-0731`): `chat_template_kwargs` с `none`/`high`/`max`
- GLM: `enable_thinking`/`clear_thinking` + top-level `reasoning_effort`
- MiniMax M3: `thinking_mode: disabled | adaptive | enabled`
- Nemotron 3.x / 3.5 Lightning: режимы через system-message / `reasoning_budget`
- Qwen-семейство: `chat_template_kwargs.enable_thinking`
- Явное **выключение** thinking, когда уровень `off` (модели типа GLM думают по умолчанию)
- Разблокировать уровни `xhigh`/`max` через model-level `thinkingLevelMap`

### P1 — актуальность каталога (метаданные и предупреждения)
- Мёртвые модели НЕ убираются из селектора: пользователь предупреждается
  (статически при выборе, динамически при ошибке запроса), решение «пробовать
  или выбрать другую» — за пользователем.
- Добавить недостающие модели живого каталога с корректными метаданными
  (контекст, maxTokens, vision).
- Способ обновления: статический оверрайд-файл в формате пи, ставится командой
  расширения; живой дискавери (см. P5) — опционально.

### P2 — нормализация запросов
- Сплющивать текстовые контент-массивы в строки для старых моделей.
- Дефолтный `max_tokens`, если модель его требует.

### P3 — индивидуальный HTTP(S)-прокси для запросов к NIM
NVIDIA в корпоративных условиях может требовать особые точки выхода трафика.
Расширение должно уметь маршрутизировать запросы провайдера `nvidia` через
отдельно заданный прокси, не трогая остальные провайдеры пи.
- Конфигурация: переменная окружения (например, `NVIDIA_NIM_PROXY` /
  `HTTPS_PROXY_NVIDIA`) и/или запись в `settings` расширения; прокси только для
  запросов к `integrate.api.nvidia.com`.
- Поведение без конфигурации — как сейчас (никакого прокси).
- Понятная ошибка, если прокси недоступен или отвергает соединение.
- Прокси применяется ко всем запросам провайдера: инференс, `GET /v1/models`
  (дискавери), пробы.
- Механику реализации выбрать после исследования (см. открытые вопросы).

### P4 — диагностика
- Показывать для 429: `retry-after` и request ID.

### P5 (опционально) — живое обнаружение моделей
- `GET /v1/models` при старте сессии, добавлять найденные модели семейства,
  фильтровать не-чат модели (эмбеддинги, reward, guard).
- В выбранной хук-архитектуре добавление моделей в селектор возможно только
  данными (оверрайд-файл), поэтому живое обнаружение — генератор обновлений
  оверрайда, а не рантайм-механика.

## Не цели

- Не подменять глобальный `streamSimple` для `openai-completions`.
- Не убирать мёртвые модели из селектора — предупреждение вместо удаления
  (решение при выборе архитектуры; вернётся как режим, если понадобится).
- Не регистрировать отдельный провайдер, если задачу можно решить правкой
  встроенного (см. ниже) — цель «улучшить встроенный», а не «ещё один провайдер».
- Не поддерживать self-hosted NIM / другие эндпоинты (только
  `https://integrate.api.nvidia.com/v1`).
- Не трогать цены/биллинг (ключи корпоративные, учёт на стороне компании).

## Ключевой вопрос — решён (архитектура D2)

Выбрана хук-архитектура **без перерегистрации провайдера** (внутренний разбор:
ветка `research/05-reference-plugins`, файлы `research/05-*.md`):

- Встроенный провайдер `nvidia` не трогается: `registerProvider` не вызывается,
  авторизация/стриминг/ретраи `ResourceExhausted`/атрибуция/`NVCF-POLL-SECONDS`
  остаются встроенными.
- **Поведение — кодом расширения**: хуки `before_provider_request` (thinking,
  нормализация) и `after_provider_response` (диагностика, предупреждения о мёртвых
  моделях); прокси — выборочный глобальный диспетчер (исследование 04).
- **Метаданные — данными**: отдельный конфиг-файл с оверрайдами в формате пи
  (схема `models.json`: `modelOverrides` по `id` + `models[]`), применяется в
  `~/.pi/agent/models.json` командой расширения; расширение владеет только своими
  записями по `id` моделей, остальные записи пользователя не трогает.
- Полная перерегистрация отклонена: риск потерять плюсы встроенного выше выгоды;
  чистка мёртвых моделей заменена предупреждениями (см. «Не цели»).
- Прокси: пи глобально уважает `HTTPS_PROXY`/`NO_PROXY`, но «только один хост»
  ими не выразить — используется выборочный диспетчер по `origin` (исследование 04).

## Критерий приёмки

1. На `nvidia/...` моделях переключение уровня мышления реально меняет запрос
   и ответ (для `off` reasoning-контент исчезает там, где это возможно).
2. Мёртвые/нестабильные модели помечены предупреждением (при выборе и при ошибке запроса); актуальные модели доступны.
3. Старые модели принимают запросы с текстовым контентом без ошибок формата.
4. 429 показывает понятную информацию о повторе.
5. Расширение не влияет на провайдеры кроме `nvidia`.
6. При заданном прокси запросы к NIM идут через него (проверяемо), запросы других
   провайдеров — нет; без конфигурации поведение не меняется.

## Референсы

Локальные копии этих плагинов лежат в `subprojects/`. Это **вендорные
референсы**: каталог в `.gitignore`, в основной репозиторий не попадает, в
рантайме не импортируется (код мы заимствуем переписыванием в `extensions/`,
см. комментарий в `extensions/transform.ts`). В копиях **не патчим**: правки
теряются при обновлении копии и создают ложное ощущение исправленности;
исправления багов чужих плагинов — PR в их апстрим.

- `pi-extension-nvidia-nim` (npm, stridertibe, v1.5.1) — источник фактов о
  семействах и проб-матрицы; архитектура через `before_provider_request`.
- `pi-nvidia-nim` (npm, xRyul) — кастомный `streamSimple`-обёрточник (антипаттерн
  для нас, но источник маппингов `chat_template_kwargs`).
- docs/custom-provider.md в поставке пи — `registerProvider`, `compat`,
  `thinkingLevelMap`, `chatTemplateKwargs`.
